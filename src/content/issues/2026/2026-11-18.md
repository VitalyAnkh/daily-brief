虚宝，早。今天是第六期，11 月 18 日，星期三。

## 爆文

Introducing GPT‑6.2 Astra and Sol，OpenAI 这是昨夜 HN 上的千分帖。要紧的不是又刷了几个榜，而是用更少的输出 token 做完更难的事。Astra 的 API 价格比 GPT‑6 Astra 降了两成，缓存输入降了六成。Sol 在 Cognition 的 FrontierCode 2.0 上只比 Astra 低 0.5 分，成本约为五分之一。各项基准的脚注比正文更有看头。

Java4Shell: Write once, RCE everywhere，Calif.io OpenJDK 在 x86‑64 上用 AVX‑512 VBMI 指令加速 Base64 解码，这条加速路径里藏着一个越界写，64 个 A 加一个等号就能触发。Keycloak、Jira、Jenkins 等在默认配置下都可能被未经认证的远程攻击者执行代码。补丁已在太平洋时间 11 月 17 日下午发布；一时升级不了，可以先用 -XX:-UseBASE64Intrinsics 关掉这条加速路径。这是一份“优化本身就是攻击面”的活教材。

Windows 11 Is Collecting Data on Which Coding Agents and Developer Tools You Use，Xusheng Li 作者让 AI 陪着翻 Windows 的二进制文件，在 MissionControlAggregator.dll 里找到一份名单，有 codex.exe、claude.exe、cursor.exe，再一路追到 DiagTrack 的上传队列。逆向过程写得干净利落，结论也清楚：只要“可选诊断数据”是开着的，你用哪些编程代理就会被编成几个比特，送往微软。

How the Claude Code team thinks about verification，Addy Osmani Claude Code 团队约九成代码由 Claude 写、由 Claude 审。文章把验证押在三类测试上：端到端测试、性质测试、差分测试，并直言把程序真正跑起来比测试更重要。可以和下面 Dan Luu 的实验对照着读。

Carmack 谈 3dfx 的灰蒙蒙色彩，John Carmack 有人问 Voodoo 1 的画面为什么发白。Carmack 的回答是：NeXT 和 3dfx 都想在色彩空间上做对的事，结果画面反而比对手难看。这是一则关于伽马与线性光的小掌故，有六千多个赞，评论区里不少老图形程序员现身说法。

## 深度

Test/verification technique effectiveness with Astra，Dan Luu 同一组实验，换了模型，结论就翻了过来。之前用 GPT‑5.6 Sol 时，要求代理做 TDD、QuickCheck、Lean，效果反倒比不加要求更差，写出来的测试多是空架子。换成 GPT‑6 Astra 后，Zstd 这个任务已经接近满分：中等算力下约花 1 美元，99% 以上的用例都能通过。于是他加码到 IMAP 和 Pandoc，后者烧了约九万美元。这一回，加上各种测试手段的效果胜过默认做法，但要说哪种手段更好，样本还不够。最可贵的是作者对自家数据的克制，他不肯从小样本里编出动听的故事。

**读后所得：** 别再凭“听上去合理”给代理指定测试方法，拿自己的任务实际量一量。

Automatic Checking of Compiler Correctness with E-Graphs，Adam Chlipala 这是 MIT 发表在 POPL 2027 的新作。给出一个从没见过的函数式语言编译器的定义，不加任何引导证明的注解，就能用 e-graph 等式饱和自动证明它是正确的。Chlipala 把它放进一个更大的主张里：一步步用经过证明的改写规则来构造程序，是眼下 AI 编程代理之外的另一条正路。文章从 System F 到类型化汇编的分阶段编译讲起，数学味很足。

**读后所得：** e-graph 不只是优化器的玩具，也可以当证明引擎用。

### Latent Lattice Language Models，Duggal、Freeman、Torralba 等（MIT 与 Adobe）

给 Transformer 加算力，常见的做法是往深处加：更多的层、循环层、潜在推理步。这篇换了一个方向：在每一层旁边加一条沿时间方向递归的潜在状态流，和纵向的残差流交织成一张网格。在 406M 参数、20B token 的训练规模下，验证困惑度从 15.41 降到 14.40，和 hyper‑connections 叠加后降到 13.61，放到 Mamba‑2 和 Gated DeltaNet 上也都有效。项目页有交互动画，值得点开慢慢看。

**读后所得：** 让每一层持有跨 token 的状态，也许是深度、宽度之外又一个可以扩展的维度。

The MacBook Pro's OLED PWM Problem，MacAnorak 新款 MacBook Pro 换上了串联 OLED 屏。Notebookcheck 测得它的调光频率最低只有 240Hz，上一代 Mini‑LED 是 14,880Hz，相差约六十二倍，部分用户因此头痛、眩晕。文章把 PWM 调光和 DC 调光讲得很明白，也没有把所有眼疲劳都怪到 PWM 头上，分寸得当。

**读后所得：** 学电子正好借此温习占空比、调制深度和人眼对闪烁的感知。用手机慢动作拍一下屏幕，就是最便宜的示波器。

### Print & Place: Using a 3D Printer for Continuous Assembly of Electronic Devices，Oliver Child、Patrick Baudisch、Mike Fraser（UIST 2026）

用的是一台没改过一颗螺丝的普通 FDM 打印机。打印到一半时，它挤一点塑料当胶水，把料盘里的小 PCB、导线、铆钉粘起来放进模型，再接着打印，把它们封在里面。成品有会发光的冰箱贴，也有会走路的小机器人。Hackaday 的报道补充了它的毛病：系统没有闭环反馈，会拾取失败、放歪、接触不良。

**读后所得：** 在电子和 3D 打印的交界处，你手边那台打印机已经能干贴片机一半的活。

## 书

### 《Visual Complex Analysis》（25 周年纪念版），Tristan Needham 著，Roger Penrose 作序，Oxford University Press，2023（Blackwell's）

复分析课本大多是一串串的估计和积分，Needham 偏要用图把它讲出来：乘以 i 是旋转，解析函数在局部就是伸缩加旋转，留数也有它的几何意义。你在学电子，阻抗、相量、传递函数都长在复平面上。这本书先把公式背后的几何立起来，日后看波特图、奈奎斯特图会更有底。

### 《The Elements of Computing Systems》（第二版），Noam Nisan、Shimon Schocken 著，MIT Press，2021（MIT Press）

它就是 Nand2Tetris：从一个与非门开始，搭出 ALU、CPU、汇编器、虚拟机、编译器，最后跑起俄罗斯方块。程序员学电子，最缺的是软件和晶体管之间那几层的手感，这本书正好补上。今天的 Java4Shell 就出在 SIMD 指令这一层，走一遍这本书，你对底下发生了什么会多一分直觉。

## 人物

### Ole Rømer（1644–1710）

三百五十年前，1676 年 9 月，这位丹麦天文学家在巴黎科学院预言：11 月 9 日，木卫一会比预期晚约十分钟从木星的阴影里出来。结果应验了。他把木卫一的掩食当成一座钟，发现地球远离木星时掩食来得晚，靠近时来得早，由此推断光速是有限的，并估计光穿过地球轨道直径大约要 22 分钟。

他做的远不止这一次测量。据维基百科，他回丹麦后做了国王的数学官，1683 年建立了丹麦第一套全国度量衡。他摔断腿养伤时，定了一套以水的冰点和沸点为参照的温标，1708 年华伦海特来访后，在它的基础上改出了华氏温标。他还发明了子午环，造了哥本哈根最早的街灯，1705 年起又当上哥本哈根的警察总长，整顿供水和下水道。可惜他的观测记录毁于 1728 年的哥本哈根大火。

值得借鉴的有两点。一是把一个周期现象当作时钟，再从时钟的“误差”里读出别的物理量，这正是今天调试电路、做性能剖析的基本功。二是他从没把搞科学和管好一座城分成两件事，在他那里，测量和制度是同一门手艺。

## 反面观点

写代码从来不是难处 眼下的共识是，AI 让重写变得廉价，旧的 C 代码库迟早会被代理成批翻译成 Rust。curl 的作者 Daniel Stenberg 在《Actual curl rewrites in rust》里泼了冷水。

他的论证有三层。第一，三周就能重写成功，恰恰是因为 curl 文档齐全、测试成千、多年来被所有模型读过，等于有一份完美的规格书；这证明的是翻译能力，不是创造能力。第二，代理把 18.5 万行 C 译成 34 万行 Rust 的那三周里，curl 本身合并了三百多个提交、两百来个修复；软件是活的，一张快照不等于一个项目。第三，2026 年确认的 81 个 curl 漏洞里，只有 14 个（17.3%）大概率能靠内存安全语言避免，换成 Rust 也还剩 67 个。他的结论是：不信任何语言的重写，只信没有尽头的打磨。

我的看法是，第三层最有力，它把内存安全从信仰拉回到统计上。前两层对 curl 成立，却不见得对所有项目成立：没有社区、没有维护者、测试也稀薄的老代码，恰恰是 AI 重写最划算的地方。更公允的说法也许是，重写值不值，取决于原项目还有多少生命力；活得越旺，克隆版越追不上。

## 公众号选题

**题目：** 《当代码不再昂贵，什么变贵了？》

**切入角度：** 同一天里，三篇文章不约而同地指向验证。Claude Code 团队说九成代码由模型来写，所以要把力气花在端到端、性质和差分测试上。Dan Luu 花了九万美元测出，测试手段好不好要拿数据说话，换个模型结论就会翻过来。Stenberg 说重写容易，追上一个活着的社区很难。写代码的成本塌下来之后，稀缺的是验证、维护和信任。

**大致结构分五段：** 

从 curl 的两个 Rust 克隆讲起：8,600 美元、三周、34 万行，以及同一时期的两百个修复。

验证的几种形态：Claude Code 团队的三类测试，以及 Chlipala 用 e-graph 自动证明，代表“构造出来即正确”的另一条路。

数据泼的冷水：在 Dan Luu 的实验里，旧模型被要求做 TDD 反而更差，新模型却能把模糊测试做得像样。

一个安全注脚：Java4Shell 说明，就连“一次编写、到处运行”的 JVM，也会在最底层的 SIMD 优化里出事。

收尾给个人开发者三条能照做的建议：先写端到端用例；给编解码类代码补上往返性质测试；重构时留着旧实现，做差分对照。
