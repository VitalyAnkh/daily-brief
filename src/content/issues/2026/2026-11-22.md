虚宝早。黎曼猜想那份 Lean 证明，社区已经集体复核完了。这件事真正值得看的，倒不是哪个模型多聪明，而是一套怎么检查、怎么信任的方法：证明本身可以没人逐行读过，但每一个检查器都要能单独站得住。这一期从这里出发，也聊到 FPGA、逆向工程、路由，以及一台显示器。

## 爆文

**[Lean and Mathlib communities：《Lean verification of the Riemann Hypothesis》](https://leanprover-community.github.io/blog/posts/riemann-hypothesis/)** — 11月21日
这份声明由 Lean FRO 和 Mathlib Initiative 背书，表态很干脆：对 Alpöge 那个 1700 万行的 Lean 库，“我们完全确信证明正确”。理由按四条判据逐一交代。第一，定理陈述用的是 Mathlib 里早经数论和 Lean 专家审过的 `RiemannHypothesis`。第二，几十个人各自编译，导出的原始证明文件完全一致。第三，社区另写了一个只依赖 Mathlib 的陈述文件，再用 `comparator` 和 `con-leche --compare` 两个独立工具比对，确认库里证明的就是这条陈述，一字不差。第四，导出的证明交给多个检查器复核，包括 Lean 官方内核、`con-leche`、`con-ron`，以及第三方用不同语言写的若干实现。其中 `con-leche` 和 `con-ron` 自带一份相对于集合论的形式证明，保证它们不会接受错误证明；而且所有检查都跑在一份“惰性”导出物上，源码里就算藏了恶意代码也碰不到。

声明最后一句是期待数学界“解释这份证明里的新想法”。机器负责“对”，人还得负责“懂”。技术细节可以看第9期荐过的 Andrew Sutherland 核验页，这里就不展开了。声明里有几处比公开日志写得更满，放在后面“反面观点”里对照着读。

**[ioma8：《LLM assisted reverse engineering》](https://www.slowchronicle.com/posts/llm-assisted-reverse-engineering)** — Slow Chronicle，11月18日
作者做软硬件逆向二十年。这篇写他现在的做法：Ghidra 通过 MCP 接给 Agent，再配上 radare2，把二进制交出去，剩下的多半能自己跑完。有两条经验很实在。一是让 Agent 把一路上的发现都写进 Markdown 笔记，上下文压缩之后不至于迷路。二是一个叫“假设调试”的技能，逼 Agent 每次只提一个假设，写进磁盘上的 CSV，设计一个能定论的实验，记下结果，再往下走，不许瞎猜着兜圈子。实现选 Rust，理由是编译器的严格反馈正好适合 Agent 迭代。

成果清单很长：给 Arturia MiniFreak、Teenage Engineering OP-Z 写了自定义固件，摸清了 Sony A7III 的通信协议，把这台相机改成了无线摄像头，还修好了 macOS 上的老 HP 打印机驱动。他说半年里做成的几件事，换作手工每件都得几年。你在学电子学，读这篇能看到“读芯片手册、抓协议、改固件”这条路的门槛正在怎样下降。

**[Oscar Molnar：《My Monitor Was Cutting My Download Speed by 75%》](https://blog.tymscar.com/posts/studiodisplayethernet/)** — The Tymscar Blog，11月15日（21日上 HN 热榜）
2.5G 对称宽带，上传 2.4G，下载只有 600M。最后查出来，问题出在接在 Studio Display XDR 上的 RTL8156B 网卡上。作者用 UDP 恒速灌包，读网卡自己的丢帧计数器，发现转发给 Mac 的速率卡在每秒约 16.8 万帧，大约 2 Gbps，再往上全丢。原因在 USB 3 的突发机制：这颗芯片的 `bMaxBurst` 是 3，一次只发 4 个 1KB 包，然后要等主机放行。显示器内部的 Hub 让一次往返多了约 7.6 微秒，加上发送 4KB 的约 8.2 微秒，出口带宽就被压到入口以下，缓冲区溢出，TCP 跟着大幅退避。换成 `bMaxBurst` 为 7 的 RTL8157 之后，一帧不丢。

文章好看在推理链条：用对照实验一层层排除，最后落到一个描述符字段上。这是学电子时很值得反复练的思路。

## 深度

**[Ankit Gupta：《Vibecoding an inference chip》](https://ankitg.me/blog/vibecoding-inference-chip/)** — 11月20日 作者没写过 Verilog，在 AWS F2 实例的 FPGA 上，让云端 Agent 跑了几天，把 DeepGrove 的三值权重模型做到逐位精确运行，速度从首个可用版本的 6.43 tok/s 提到 213 tok/s，约 33 倍。实验历史里累计写了约 300 万行代码，token 花费约一万美元。

文中的优化日志最耐读。提速几乎都来自一连串约 1.5 倍的小改进复利叠加：突发读取 KV cache、并行 MoE 路由、专门处理 norm 和 RoPE 的“胶水引擎”、推测解码、权重打包，最后为了稳定，把时钟主动降一档。作者还让 Agent 复盘人类建议到底起了多大作用。结论是设计点子它大多自己也想得到，真正立刻见效的是两条流程纪律：别跑几个小时的仿真，以及“逐位精确”这个正确性约束。人还有用的地方，在于定义怎么快速迭代、什么才叫对。

**[Ben Brubaker：《Network Researchers Nail Down Theory of ‘Perfect Resilience’》](https://www.quantamagazine.org/network-researchers-nail-down-theory-of-perfect-resilience-20261120/)** — Quanta Magazine，11月20日 路由器只能凭本地信息转发：目的地、包从哪条链路进来、相邻哪些链路断了。在这种限制下，什么样的网络能保证只要源和目的之间还连通，包就一定送得到？2012 年 Godfrey、Schapira 等人提出这个问题。Schmid 在 2020 年把它接到了图子式理论上：Robertson–Seymour 定理保证坏结构只有有限多个，但没说有几个。今年 Bentert 和 Schmid 在 STOC 上给出完整答案，正好四个禁用子式。避开它们的网络，都可以用迷宫里“一路右转”式的规则实现完美韧性。

有点讽刺的是，这四个结构太简单，连接越密的网络反而越容易含有它们。一篇难得的“问题被彻底说清楚”的报道。

**[Stefan Hermann：《Prusa CORE One INDX Review: A Mess, but I Love It》](https://www.cnckitchen.com/blog/prusa-core-one-indx-review)** — CNC Kitchen，11月15日 十周、近四万次换头的长期实测。Bondtech INDX 系统有八个靠感应加热的被动工具头，升级套件 999 美元，整机 2369 美元。最亮眼的是省料：《梦见岛面具》4321 次换头，打了 42 小时，不用擦料塔，只留下约 40 克废料，大约是 Bambu H3C 的五分之一。短板同样写得很清楚：切片软件的速度不一致导致曲面上有细微挤出波动，悬垂冷却不如 Bambu，灯条装在热床下方，看不到首层。你要是在看多色打印，这篇比任何宣传页都诚实。

**[Shalma Wegsman：《How M.C. Escher’s Art Creates Bizarre Mathematical Worlds》](https://www.quantamagazine.org/how-m-c-eschers-art-creates-bizarre-mathematical-worlds-20261118/)** — Quanta Magazine，11月18日 借纽约数学博物馆 MoMath 的 Escher 展，梳理他的数学来路。在阿尔罕布拉宫迷上镶嵌；从同父异母的哥哥寄来的 Pólya 论文里认识了 17 种平面对称群；晶体学家 MacGillavry 发现他对“色彩对称”的理解超过同行；与 Coxeter 通信之后，Escher 从一张双曲平面镶嵌图里拆出了圆弧的规律，画出《圆极限》系列。直觉先到，理论后到，这个顺序本身就很有意思。这些图样拿来做 3D 打印的镶嵌件，也很合适。

## 书

《Graph Theory》第六版，Reinhard Diestel 著，GTM 173，Springer，2025；[作者书站](https://diestel-graph-theory.com/) 现代图论的标准教材。证明简洁而完整，每章都会用一两个较深的结果领读者看到前沿方法。图子式一章正是读懂今天 Quanta 那篇、以及下面 Paul Seymour 工作的最好入口。官网有正文免费在线预览、配套课程录像，也有价格不高的 PDF 电子版。

《Tabular Foundation Models: A short and opinionated guide》，Christoph Molnar 著，2026，[免费在线](https://tabularfoundationmodels.com/) 《Interpretable Machine Learning》作者的新书。TabPFN、TabICL 这类模型在数百万份以模拟数据为主的数据集上预训练，预测时把训练集当作上下文喂进去，不调参，也不更新权重。书很短，观点鲜明，分三部分：原理（PFN、上下文学习、预训练）、实操（分类、回归、分位数回归、时间序列）、要不要押注。表格数据是工程里最常见、却最少被大模型话题照顾到的一块，这本书补上了。

## 人物

Paul Seymour 简介可见 [Wikipedia](https://en.wikipedia.org/wiki/Paul_Seymour_(mathematician))。1950 年生于英国普利茅斯，现任普林斯顿大学 Albert Baldwin Dod 数学教授，英国皇家学会会士，四获 Fulkerson 奖。他和 Neil Robertson 从 1980 年代起合作，写出二十余篇系列论文，证明了图子式定理：任何在取子式下封闭的图类，都只由有限多个禁用子式刻画。这个定理只断言“有限”，不告诉你有几个、是哪几个。今天 Quanta 那篇里，Bentert 和 Schmid 花了几年时间，就是把“有限”落实成“恰好四个”。

Seymour 的工作还贯穿四色定理的新证明、强完美图定理、Erdős–Hajnal 猜想等。他在 Bellcore 做过十三年研究员，是那种在工业实验室里做出最纯粹的数学的人。

## 反面观点

主流共识：Lean FRO 与 Mathlib Initiative 已经背书，这份证明可以“完全确信”，事情翻篇了。

**[sysnote：《Lean FRO and Mathlib certify Alpöge's Lean proof of the Riemann Hypothesis: what was checked, and by what》](https://sysnote.net/news/lean-fro-and-mathlib-certify-alpoge-s-lean-proof-of-the-riemann-hypothesis-what)** — 11月21日 作者把声明和两份公开记录对读：Sutherland 的核验页，以及 leanprover-community 仓库里的核验笔记。结论不是证明有错，而是声明写得比日志宽。声明说导出物已交给 Lean 官方内核、con-leche 和 con-ron 等检查器，后两者还自带一份相对于集合论的形式证明，保证不会接受错误证明。公开日志却更窄：随 Lean v4.36.0 附带的 con-leche 和 con-ron 对这份导出物以退出码 2 拒绝运行，原因是不支持其中一种自反归纳类型。这是拒绝执行，不是判定证明为假。真正接受导出物的 con-leche，是 11 月 17 日、也就是证明公布前三天的 master 构建，并非随 Lean 发布的那一版。作者没有找到 con-ron 接受这份导出物的公开日志。社区仓库的 comparator.json 因此只把 Lean 的 paranoid 内核和用 Rust 写成的 nanoda 列为额外检查器。声明还说“几十人”编译出了同一份导出文件，仓库笔记里明确记录的第二次成功构建只有一回，而且“这些构建都没有在沙箱里进行”。

另外两处也值得看。一是源码里有若干绕过精化器类型核对的策略（如 `kexactB`、`kcopy`），这些证明只能靠内核把关，这也正是必须用独立检查器重放导出物的原因。二是工程钉在 Lean v4.33.1，这一版早于 4.34.1 里两处运行时修复；按核验笔记的读法，在故意构造的输入下，官方内核理论上有可能据此证出 `False`，所以一次成功编译本身“证据有限”，真正的判断要留给 4.36.0 和独立检查器。nanoda 用 Rust 写成，不受 Lean 运行时那些问题影响。

我的掂量：这并不能把认证推翻。两套独立的内核设计（Lean 与 nanoda），外加一份开发中的 `con-leche`，都接受了同一份导出物，分量已经很重。作者自己也说，指出的几处都不意味着证明有错。真正有价值的是方法：这一期的主题既然是“判据比产出更值钱”，那么社区那份“完全确信”的声明，本身也是一份判据，应当拿原始日志对一遍。声明多写出去的那一截，不减损已经做成的检查，但提醒我们：信任要落在公开的记录上，而不是落在措辞最满的那一句上。至于“懂”，声明并不假装已经完成。文中转引 Andrew Granville 对 Nature 的评论，说 Alpöge 那四页短文写得含混；Alpöge 自己也表示要简化论证、再写成可读的文章。核验过了，解释还在后头。

## 公众号选题

**题目：《机器写得越多，“怎么算对”越值钱》**

切入角度：不谈 AI 能不能写代码、能不能证明定理，只谈一件更具体的事。当产出变便宜，验收标准就成了新的源代码。

大致结构：
1. 开场一个场景。1700 万行的 Lean 证明，没有人逐行读过，社区却敢说“完全确信”。他们信任的不是证明本身，而是四条事先写好的判据，加上几个彼此独立、甚至自带形式证明的检查器。
2. 三个现场，三种“判据”。数学上，Lean 社区把陈述单独抽出来，用两个工具交叉比对。硬件上，Ankit 给 Agent 定下“逐位精确”的铁律，Agent 复盘时承认，最见效的人类输入正是这条约束和迭代节奏。逆向工程上，ioma8 逼 Agent 每次只提一个假设，写进 CSV，用实验定论。三处的共同点是：人不再动手做每一步，而是定义什么叫完成、什么叫错。
3. 一个反例，说明判据从哪里来。Oscar Molnar 那台显示器没有 Agent 出场，全靠对照实验和对 USB 突发机制的理解，一层层排除到一个描述符字段。会提好问题、会设计能定论的实验，这种能力只能从亲手排查里长出来。
4. 一个理论注脚，说明“彻底理解”有多稀有。Quanta 报道的完美韧性问题，Robertson–Seymour 定理早就保证答案有限，但把“有限”变成“恰好四个”，还是花了十几年。判据写得好，背后是对问题结构的真正理解。
5. 落点接声明与日志之间的缝隙：验收标准写出来之后，还要对着原始记录读一遍。给读者一个可操作的建议：收到一份“已经验证”的结论时，先问四件事——陈述是不是事先独立写好的、检查器是不是声明里点名的那几个、日志是否公开、还有哪些检查仍在跑。
